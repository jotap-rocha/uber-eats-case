## Regras de inicialização

Ao iniciar uma conversa relevante para o código ou a documentação deste repositório:

1. Leia `CONTEXT.md` na raiz (onboarding rápido). Se não existir, leia o `README.md` principal.
2. Se existir, leia `docs/00-INDEX.md` (ou o índice principal da pasta `docs/`) para saber onde está cada guia.
3. Se o repositório tiver ecossistema Cursor em `.cursor/`:
   - Para escolher papel e escopo: considere `.cursor/commands/core/router.md` **ou** o agente “roteador” indicado pelo time.
   - Para listar agentes e exemplos de `@`: use `HOW_TO_USE_AGENTS.md` (se existir) ou navegue em `.cursor/agents/`.
   - Knowledge bases: `.cursor/kb/` e, se houver, `.cursor/kb/_index.yaml`.

- Ambiente real: quando possível, **execute** verificações (testes, linters, comandos) em vez de apenas sugerir que o humano rode.

## Regras de código e arquitetura

- **Clean Code** e **SOLID**; nomes claros; funções e módulos com responsabilidade única.
- **Python:** type hints em APIs públicas; `pytest` para testes quando o projeto já o utilizar.
- **Dados / Spark (se aplicável):** prefira DataFrame API a RDD; documente suposições de partição e volume.
- **Web / API (se aplicável):** validação de entrada, tratamento de erros explícito, evitar vazar detalhes internos em respostas.
- Alinhe-se ao estilo do repositório (formatador, linter, estrutura de pastas) antes de introduzir padrões novos.
