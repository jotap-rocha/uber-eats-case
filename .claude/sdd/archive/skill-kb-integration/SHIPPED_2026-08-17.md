## Lessons Learned

### Process

- Rodar uma **verificação independente** (agentes "frios", sem o viés de quem implementou) depois
  do `/build` e antes do `/ship` valeu a pena: achou 2 bugs reais que os próprios Acceptance Tests
  do DEFINE não cobriam (porque os ATs testavam *existência/menção*, não *corretude do conteúdo*).
  Vale considerar isso como passo padrão em features que tocam convenções cross-cutting.
- Um agente em background que recebe escopo de "só uma fase" pode encadear fases seguintes sozinho
  se não for explicitamente contido — em uma sessão anterior deste mesmo projeto isso causou race
  condition em arquivos de manifest. Nesta feature, evitei o problema executando `/brainstorm`,
  `/define`, `/design` e `/build` diretamente na conversa principal (não delegando a agentes
  autônomos em background para as fases interativas/sequenciais).

### Technical

- **Nem todo "mirror" é realmente espelhado**: KB (`kb/`) é genuinamente replicada em
  `.cursor/`, `.claude/`, `.github/` — mas Skills (`skills/`) não são; só `.claude/skills/` é
  escaneado pelo Claude Code. Assumir que todo diretório sob os 3 prefixos segue o mesmo padrão de
  espelho foi a causa raiz do bug mais sério desta feature (paths de Skill sugeridos "por mirror"
  nas rules). Antes de replicar um padrão de mirror para um conceito novo, confirmar
  explicitamente se ele é de fato replicado.
- `scripts/validate-agent-router.py` só abre `.cursor/sdd/architecture/AGENT_ROUTER.yaml` — não
  valida os mirrors `.claude`/`.github`, nem valida o conteúdo de `skill_reference`. Uma mudança
  estrutural no router pode "passar" na validação e ainda assim estar incorreta nos mirrors.

### Communication

- As perguntas de brainstorm com opções recomendadas (multiple-choice, uma por vez) mantiveram a
  feature enxuta — todas as 4 perguntas convergiram rápido para a opção recomendada, sem idas e
  vindas, e o corte YAGNI resultante (5 itens fora de escopo) evitou trabalho desnecessário.

## Definition of Done — documentação de uso do projeto

Avaliado conforme checklist do `ship-agent`: esta feature **não** altera como o repositório é
executado, navegado ou depurado no dia a dia (não há novo comando, script ou fluxo de execução) —
é uma convenção de autoria de conteúdo, relevante só quando alguém for criar Skill/KB nova. Por
isso, `CONTEXT.md`, `.cursorrules`/`.claude/CURSOR.MD` e `.claude/commands/core/router.md` **não**
foram atualizados nesta feature. Se no futuro a convenção `skill-first` passar a ser citada como
parte do onboarding padrão, reavaliar.
