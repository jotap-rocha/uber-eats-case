## Lessons Learned

### Process
- Investigar a viabilidade técnica do ShadowTraffic (lookup cruzado Postgres×MinIO) via documentação oficial *antes* de abrir a feature, na Onda 1, evitou abrir escopo sobre uma capacidade não confirmada.
- Rastrear todas as referências aos 3 containers antigos no Build revelou 7 arquivos extras (scripts, docs) que ficariam quebrados se não fossem corrigidos junto — vale sempre fazer essa varredura antes de considerar "pronto".

### Technical
- A migração de PK UUID→sequencial só se aplica a um volume Postgres **novo**: os scripts em `sql/*.sql` só rodam via `docker-entrypoint-initdb.d` na primeira criação do volume. Recriar (`docker-compose down -v` + subir de novo) foi necessário e confirmado por inspeção direta do schema.
- Dependência externa (licença da imagem `shadowtraffic/shadowtraffic:latest` expirada) bloqueou a geração de dados e, por consequência, os testes de join real no Gold — um lembrete de que a validação de infraestrutura local pode depender de terceiros fora do controle do projeto.

### Communication
- O critério formal de sucesso (Success Criteria do Define) incluía joins 0-órfãos no Gold com dados regenerados; o usuário aceitou fechar a feature com a validação de schema (PK sequencial + campos novos confirmados via `\d users`/`\d drivers`) como suficiente, adiando a validação de dados para depois da renovação da licença ShadowTraffic. Decisão consciente do dono do projeto, registrada aqui para não ser confundida com lacuna não percebida.

## Pendência conhecida (não bloqueante para o ship)

AT-002 a AT-007 (geração de dados via ShadowTraffic + joins reais pedido↔usuário/motorista no Gold) não foram executados — a imagem `shadowtraffic/shadowtraffic:latest` recusou rodar por licença expirada. Quando a licença for renovada: rodar `.\scripts\start-all.ps1` (ou reiniciar só `gen-unified`), regenerar os dados, rodar o pipeline Databricks completo e conferir os joins listados no `BUILD_REPORT_UNIFICACAO_IDENTIDADE_POSTGRES_MINIO.md`.
